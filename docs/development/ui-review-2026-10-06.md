# ClassLoom UI reform verification

Date: 2026-10-06. Branch: `feature/ui-structural-changes`.

## Scope and design decisions

Read the ClassLoom skill, root `AGENTS.md`, root `DESIGN.md`, and `apps/web/DESIGN.md` before implementation. The concrete foundation is in [design-system.md](design-system.md). The source design documents remain authoritative.

Replaced the legacy global stylesheet with semantic light and dark tokens. Rebuilt the authenticated shell, permission-aware navigation, live overview, authentication frame, page hierarchy, shared field controls, profile editors, responsive record views, and recovery states. Feature screens now compose the same primitives across People, Enrollment, CSV imports, Academic Setup, Admissions, Timetable, Attendance, Finance, and Examinations. Removed the obsolete Phase 0 navigation stub and its obsolete test.

The work changes the web presentation and client interaction states. API authorization, domain contracts, database schemas, and existing workflow rules are unchanged. No dependency or UI library was added. Existing shadcn Base UI components were reused; the shadcn MCP registry and component audit checklist were inspected.

## Issues found and corrected

- Calendar icon-button sizing and the modal scrollbar gutter caused the seventh column to clip at 320px. The modal picker now uses viewport positioning, collision shifting, and full-width phone scroll locking. Measured width is 316px within the 320px viewport; every day and navigation control is 44×44px, and the final column passes a pointer hit check. Future attendance dates remain disabled; selection, Close, and Escape return focus to the date field. Birth-date year selection was also exercised on a phone (2015), with a 44px control height.
- Timetable editor selections initially exposed IDs before opening their popups. All editor choices now use the shared labeled Base UI selector; an automated regression asserts readable section, subject, teacher, and weekday values.
- Phone attendance choices hid their labels and had narrow targets. They now use four labeled controls in a two-column arrangement.
- Dropdown options and breadcrumb links follow the mobile touch-target rule; a phone academic-session option measured 44px high.
- Student admission sections touched after adding a disabled fieldset. Section rhythm now belongs to that fieldset and remains visible at intermediate and phone widths.
- The new-enquiry screen briefly claimed that a user had no school access before its request completed. It now distinguishes loading, request failure with retry, and a genuine permission-empty result. Academic-option failure also explains the available next step.
- Academic Setup could describe a successful write as a failed save when the follow-up refresh failed. It now confirms the write, explains that a refresh is needed, and prevents duplicate edits until recovery.
- Long profile identity and facts pushed staff task navigation too far down. Identity appears once, and task tabs precede the detailed profile content.
- Competing finance forms now use task tabs and retain draft values when switching. Failed requests preserve entered payment amounts.
- Record actions, scroll regions, calendar popovers, and destructive confirmations have descriptive names. Initial-context failures offer explicit page recovery without discarding an open editable record.
- When the API stopped during the final review, sign-in fell back to generic feedback. The same-origin web auth proxy now returns an uncached 503 with a specific account-service retry message when it cannot reach the API, while preserving server validation and its allowed paths. The local API was restarted and sign-in was recovered.

## Accessibility and contrast

Checked semantic page headings, persistent labels, shared descriptions/errors, focus rings, tab selection, named table scroll regions, textual statuses, responsive overflow, disabled prerequisites, and dialog bounds. Guardian editor close returned focus to its trigger; examination dialog close also returned focus to its creation action. Destructive timetable confirmation initially focused Cancel. Motion uses short transitions with a reduced-motion override.

Contrast ratios were calculated from the actual solid theme token values using WCAG relative luminance:

| Pair | Light | Dark |
| --- | --- | --- |
| Muted text / card | 5.73:1 | 8.16:1 |
| Muted text / page | 5.29:1 | 9.21:1 |
| Primary button white text / primary | 5.88:1 | 4.82:1 |
| Input indicator / card | 3.52:1 | 3.93:1 |
| Input indicator / page | 3.26:1 | 4.43:1 |
| Input indicator / muted surface | 3.10:1 | 3.28:1 |

Semantic success, warning, danger, and info text also exceed 4.5:1 against their paired soft surfaces. Color supplements labels rather than replacing them. These checks are not a formal accessibility certification.

## Limits and follow-up

- Safari, Firefox, screen readers, and physical touch devices were not run.
- The demo school had no admissions cases. Case detail and decision layouts were structurally refactored and their workflow tests passed; a populated live case was not visually reviewed.
- The active account had one workspace. The multi-workspace selection UI was refactored, but a real multi-membership browser selection was not exercised.
- CSV mapping/preview/commit and server validation failures were exercised in automated tests; no new CSV was committed during this browser review.
- Root error boundaries compile and provide recovery. A deliberate root-layout crash was not injected into the running application.

Local screenshots are kept outside version control in `.local/reviews/ui-reform/`: `students-desktop.png`, `attendance-phone.png`, `examinations-desktop-dark.png`, and `calendar-320.png`.
